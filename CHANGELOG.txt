[ 1.2.0 ]
- Fixed cascade groups leaking across activities: dropping a window into a spot that had a group on another activity joined it, moved that activity's windows and could switch to it
- Cascade groups now belong to one activity and one virtual desktop; a window on several activities can be in a different group on each, and switching lays out the groups of what is showing
- Stable cascade groups: windows keep a fixed order and the active window is always bottom-right; focusing a window in a group rotates the group to it, after a short pause so that dragging a window out never moves it first
- Ctrl+} still brings the top-left window to the front, walking round the whole group
- Moving a window into a group's spot with Meta+arrow keys joins the group; moving a member to another spot leaves it
- Cascade groups follow KWin's tile split: a group fills its windows' actual tile, wherever the split is, and is laid out again when the split is dragged; resizing a window in a group no longer takes it out
- Fixed the gap between tiled windows going missing when KWin's tile split was away from the half or quarter points, or after resizing a neighbouring tiled window
- The top and bottom halves can hold cascade groups
- Focus, Ctrl+} and activity switches only move the windows of the groups involved; the gap pass on a switch only visits windows on the current activity and desktop
- Cascade groups are indexed by activity, desktop, screen and tile spot (new file 036_cascade_index.js); nothing is stored on KWin window objects any more

[ 1.1.3 ]
- Supports Plasma 6.8 (and still 6.5 to 6.7)
- Fixed gaps no longer being applied under Plasma 6.8 (KWin 6.8 rectangles no longer expose left/right/top/bottom)
- Fixed windows resizing themselves when placed near other windows: windows next to each other are no longer shrunk to make a gap; the gap between tiled windows comes from the tile positions
- Only tiled and maximized windows get gaps; floating windows keep the size and position you give them
- A floating window dropped close to a quick-tile spot, or against a screen edge, is now quick-tiled there with gaps; dropped anywhere else, it stays as dropped
- Removed restoring a window's tiled size after it is dragged out of a tile (KWin 6.8 removed the quickTileMode it relied on)
- Fixed a window restored from maximized having its restored size changed
- Refactored the window classes (WindowGeometry, BaseWindow, TileableWindow, CascadeGroup)
- Added tests for screens whose work area doesn't start at 0,0 (thanks to Felix Jara, #12)

[ 1.1.2 ]
- Pressing the cascade shortcut again cycles through the windows in a cascade group
- Improved cascading of windows that share a tiling slot
- Closed windows are now removed from their cascade group

[ 1.1.1 ]
- Fixed windows shrinking or vanishing while being dragged
- Tiled windows now restore their tiled dimensions after being dragged and released
- Fixed gaps not being re-applied after a drag/resize completes

[ 1.1.0 ]
- Refactored core logic into TileableWindow, ActiveWindow, and TileableWindowGeometry classes
- Fixed maximized windows not receiving gaps on auxiliary screens (screens without a panel)
- Fixed static class field syntax incompatibility with KWin's JS engine
